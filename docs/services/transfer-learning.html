Transfer Learning · Domain Adaptation

Transfer Learning Across Related Domains

How to use knowledge from a source domain without assuming that another building, product, region, or cohort behaves the same way.

Discuss transfer learningRead the documented example

Transfer learning can reduce the cold-start burden when a target domain has little history and related sources contain useful structure. It can also introduce negative transfer when source and target differ in important ways. The central task is to test which patterns are shared and which are not.

Source-to-target checklist

  1. Describe the domains. Compare the process, target definition, measurement units, time resolution, operating calendar, and data-generation mechanism.
  2. Check feature compatibility. Align time zones, missing-value rules, units, categorical definitions, and feature availability at prediction time.
  3. Choose candidate sources. Use operational context and pre-defined similarity checks; do not select sources based only on correlation observed in the test period.
  4. Establish target-only baselines. Measure what can be achieved with target history alone before adding source information.
  5. Test transfer variants. Compare shared features, pooled models, target fine-tuning, temporal profiles, or domain-adaptation approaches under identical chronological splits.
  6. Watch for negative transfer. Report per-domain and per-horizon performance so an aggregate improvement does not hide a target-specific regression.
  7. Plan updates. Track how source and target conditions change and decide when a model must be recalibrated, adapted, or retrained.

Cross-building example at TalTech

In a building-energy forecasting research internship at TalTech, four adjacent buildings were repurposed as virtual sensors to represent campus activity. A 12-member ensemble combined LightGBM, XGBoost, and temporal profiles. The signed recommendation letter describes this as a cross-building transfer-learning approach and reports a blind test across 7,344 hourly observations with 12.42% MAPE and a 0.9456 correlation coefficient.

Read the full case study for the data constraint, documented results, and limitations.

Do not assume transfer is automatic: the source domain, target, evaluation window, and acceptance criteria must be examined for each project.

Potential B2B work

Scoped support can include source-domain assessment, feature compatibility review, baseline and transfer experiments, domain-shift analysis, and model evaluation. For a systems architect or data science team, these steps can provide a practical evidence base before committing to a larger production change.

A useful first discussion includes the target domain, source candidates, forecast horizon, available labels, and how success will be measured.
